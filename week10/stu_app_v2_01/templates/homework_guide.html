第2题：什么是中间件？在数据库应用系统中使用中间件有什么好处？

定义：中间件是为应用程序访问各类数据库提供统一接口的软件，屏蔽不同DBMS的差异。

好处（至少答出3-4点）：

  • 降低学习成本：开发者只需学习中间件提供的统一API，无需了解每种DBMS的具体接口
  • 降低代码耦合：SQL代码集中在中间层，应用层只调用方法，便于维护
  • 便于DBMS迁移：从MySQL换到PostgreSQL只需修改中间件层，上层代码不受影响
  • 提升安全性：可统一使用参数化查询防止SQL注入，集中管理连接和事务
  • 减少通信量（配合存储过程）：应用程序不传递SQL代码，只传递过程名和参数

结合本项目：本项目中的 database.py 就是中间件层，Flask应用通过 Database 类访问MySQL。

第3题：嵌入式SQL中，SQL通信区（SQLCA）和共享变量分别起什么作用？

SQLCA（SQL Communication Area）的作用：

  • 是一个结构体变量（如 struct sqlca），用于向主语言传递SQL语句的执行状态信息
  • 包含：SQL执行成功/失败的状态码（sqlca.sqlcode）、错误信息、影响行数等
  • 使主语言能够根据执行状态控制程序流程（如判断是否继续FETCH、是否回滚事务）

共享变量的作用：

  • 双向数据传递的桥梁：主语言变量与SQL语句之间共享数据
  • 主语言 → SQL：将应用程序中的参数传递给SQL语句（如WHERE条件值、INSERT的值）
  • SQL → 主语言：将SQL查询结果（如SELECT返回的字段值）传递给主语言进一步处理
  • 在C程序中用 EXEC SQL BEGIN/END DECLARE SECTION 声明，SQL中通过 :变量名 引用

两者关系：共享变量传递"业务数据"，SQLCA传递"执行状态数据"，缺一不可。

第4题：存储过程相比嵌入式SQL有哪些优点？

答题框架（至少4点）：

  • 运行效率高：存储过程经编译和优化后以二进制形式存储在服务器，可直接执行；而嵌入式SQL需要先编译再执行
  • 降低通信量：不传递SQL代码，只传递过程名和参数，减少网络传输开销
  • 提升安全性：应用程序中无嵌入式SQL代码，SQL代码不外泄，避免SQL注入攻击
  • 降低耦合性：用户交互（应用层）与数据处理（存储过程）分离，各自独立优化
  • 便于复用：多个应用可共享同一个存储过程，避免代码重复
  • 便于维护：DBA可独立优化存储过程，无需修改应用代码

二、分析题（共40分）

第1题（20分）：程序中定义了一个游标SX，游标的作用是什么？为什么需要游标？

游标的作用：

  • 游标是存放SQL查询结果集的缓冲区，相当于一个指向结果集中某条记录的指针
  • 通过游标，应用程序可以逐条访问查询结果中的记录
  • 游标支持一系列操作：声明（DECLARE）、打开（OPEN）、读取（FETCH）、关闭（CLOSE）

为什么需要游标？

  • SQL是集合操作语言：一条SELECT语句返回的是一个集合（多行数据），一次操作面向整个集合
  • 宿主语言是过程操作语言：C、Python等高级语言一次只能处理一条记录，需要循环逐行处理
  • "阻抗不匹配"问题：SQL的集合操作方式与宿主语言的过程处理方式之间存在不匹配
  • 游标作为桥梁：将集合结果逐条传递给宿主语言处理，解决了上述不匹配问题
  • 类比：游标就像数组的索引指针，FETCH 相当于 array[i++]

结合PPT代码：

EXEC SQL DECLARE SX CURSOR FOR
    SELECT ID, Name, Sex, Age FROM Student WHERE Dept = :S_DeptName;
EXEC SQL OPEN SX;        -- 打开游标，执行查询，指针指向第一行前
while(1) {
    EXEC SQL FETCH SX INTO :S_SID, :S_SName, :S_SSex, :S_SAge;
    // 每次FETCH将游标指向的当前行数据读入共享变量
}

第2题（20分）：EXEC SQL FETCH SX INTO ... 语句完成了什么功能？程序如何判断FETCH是否成功？

FETCH语句的功能：

  • 定位：将游标指针指向结果集的"当前行"（首次FETCH指向第一行，之后每次自动下移一行）
  • 读取：将当前行的各列数据读取到 INTO 后面指定的共享变量中
  • 传递：使宿主语言（C程序）能够获得SQL查询结果的具体数据，进行后续处理

判断FETCH是否成功：

  • 通过检查 SQL通信区（SQLCA） 的状态码来判断
  • 具体代码：if (sqlca.sqlcode != 0) break;
  • 成功：sqlca.sqlcode == 0，表示成功读取一行数据，继续循环处理
  • 失败/结束：sqlca.sqlcode != 0，表示：
    • 结果集已经遍历完毕（所有记录已处理完）
    • 或者执行过程中发生了错误
  • 程序通过 break 跳出循环，结束游标处理

完整处理流程：

EXEC SQL OPEN SX;           // 1. 打开游标（执行SQL查询）
while(1) {                  // 2. 循环逐行处理
    EXEC SQL FETCH SX INTO ...;  // 3. 读取当前行到共享变量
    if (sqlca.sqlcode != 0)      // 4. 检查SQLCA状态
        break;                   //    非0 = 无数据或出错，退出
    // 5. 处理数据（输出、修改等）
}
EXEC SQL CLOSE SX;          // 6. 关闭游标，释放资源
