数据库中间件（DB Middleware）

中间件是为应用程序访问各类数据库提供统一接口的软件，降低学习成本，屏蔽不同 DBMS 的差异。

本项目的三层架构

表现层

app.py + templates/

Flask 路由处理 HTTP 请求
HTML 模板渲染用户界面
接收用户输入，调用中间层

不包含任何 SQL 代码
不直接访问数据库

→

中间件层

database.py

Database 类封装所有 SQL 操作
提供统一的数据访问方法
参数化查询防止 SQL 注入
管理连接、事务、游标

更换数据库只需修改本层
上层代码不受影响

→

数据层

MySQL DB06

student / course 表
student_course 选课表
fn_GetTotalCreditBySID 函数
sp_CourseStat 存储过程

为什么需要中间件？

问题没有中间件有中间件
代码耦合 应用程序代码中到处散落 SQL 语句，难以维护 SQL 集中在 database.py，应用层只调用方法
DBMS 迁移 从 MySQL 换到 PostgreSQL 需要修改所有代码 只需修改 database.py 一个文件
安全性 容易忘记参数化查询，导致 SQL 注入漏洞 统一使用参数化查询，集中防范
学习成本 开发者需要了解每种 DBMS 的具体 API 开发者只需了解中间层提供的统一接口
连接管理 每个开发者自己管理连接，容易泄漏 中间件统一管理连接生命周期

代码示例：本项目中间件的实际体现

表现层 (app.py) — 不写 SQL，只调用方法

# Flask 路由：处理用户请求
@app.route('/students')
def student_list():
    # 不直接写 SQL！通过中间层获取数据
    students_data = db.get_all_students()

    # 对每条记录调用数据库函数（函数调用也通过中间层）

中间件层 (database.py) — 封装所有 SQL

# Database 类：统一的数据访问接口
class Database:
    def get_all_students(self):
        """查询所有学生"""
        sql = "SELECT ID, Name, Sex, Age, Dept FROM student"
        self.cursor.execute(sql)
        return self.cursor.fetchall()

    def call_fn_get_total_credit(self, student_id):
        """调用自定义函数"""
        sql = "SELECT fn_GetTotalCreditBySID(%s) AS TotalCredit"
        self.cursor.execute(sql, (student_id,))
        return self.cursor.fetchone()['TotalCredit']

    def call_sp_course_stat(self, course_id):
        """调用存储过程"""
        self.cursor.execute("CALL sp_CourseStat(%s, @avg, @max, @min, @pass, @total)",
                            (course_id,))
        self.cursor.execute("SELECT @avg, @max, @min, @pass, @total")
        return self.cursor.fetchone()

中间件架构的额外好处

存储过程 + 中间件 = 更强的安全性

应用程序不传递 SQL 代码到数据库服务器，只传递存储过程名和参数：

  • SQL 代码不会在网络上明文传输，避免泄露
  • 杜绝 SQL 注入攻击（没有 SQL 语句可被篡改）
  • DBA 可以独立优化存储过程，不影响应用代码
